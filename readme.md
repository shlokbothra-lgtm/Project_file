# Shortest-Path Planning in a Large-Scale Road Network (Dijkstra vs A*)

This project compares Dijkstra's algorithm and A* on subgraphs of a real road network (US Great Lakes region,
DIMACS 9th Challenge). Both algorithms are implemented from scratch in C++ using a min-priority queue and an
adjacency-list graph. No library shortest-path routines are used. Python is used only for preprocessing and plots.

## Dataset

- **Name:** USA road network, Great Lakes region (LKS), distance graph
- **Source:** 9th DIMACS Implementation Challenge, Shortest Paths (2005-2006), derived from US Census Bureau TIGER/Line data
- **Download page:** http://www.diag.uniroma1.it/challenge9/download.shtml (section *USA road networks*, *Great Lakes*, distance graph)
- **Files used:**
  - `USA-road-d.LKS.gr.gz`: arcs with distance weights
  - `USA-road-d.LKS.co.gz`: node coordinates (longitude, latitude in units of 10^-6 degrees)
- **Full graph:** 2,758,119 vertices, 6,885,658 directed arcs
- **Graph model:** vertex = road intersection or endpoint, edge = road segment (stored as two directed arcs),
  weight = road distance from the distance graph

## How to run

Run all commands from the project root. The commands use the PowerShell form (`.\program`); on Linux or macOS write
`./program` instead.

### 1. Get the dataset

Download `USA-road-d.LKS.gr.gz` and `USA-road-d.LKS.co.gz` from the page above and place them in `raw/`.
Leave them compressed: `preprocess.py` reads `.gz` and plain files. (If your browser renamed them, for example to
`USA-road-d_LKS_gr.gz`, pass the actual file names in the next step.)

### 2. Preprocess

```
python preprocess.py --gr raw/USA-road-d.LKS.gr.gz --co raw/USA-road-d.LKS.co.gz --outdir data
```

This writes, for each size N (number of vertices) in {1000, 5000, 10000, 25000, 50000, 100000}:

- `data/graph_N_edges.csv`: columns `u,v,w` (0-indexed, renumbered, directed arcs)
- `data/graph_N_nodes.csv`: columns `id,orig_id,lat,lon` (degrees; `orig_id` is the DIMACS id)
- `data/queries_N.csv`: columns `source,target` (10 reachable pairs per size)

and `data/stats.csv` (vertices, arcs, average and maximum degree), `data/cleaning_report.json` (cleaning counts, seed
vertex) and `data/heuristic.json` (comparison of edge weights with haversine distance, see *Preprocessing details*).
Options: `--sizes`, `--seed` (default 42), `--queries` (default 10), `--full` (also write the whole graph).

### 3. Compile

```
g++ -O2 -std=c++17 cpp/partB_all.cpp        -o partB_all
g++ -O2 -std=c++17 cpp/partC_dijkstra.cpp   -o partC_dijkstra
g++ -O2 -std=c++17 cpp/partD_astar.cpp      -o partD_astar
g++ -O2 -std=c++17 cpp/partE_experiments.cpp -o partE_experiments
```

Always compile with optimisation (`-O2`), since it affects the timings.

### 4. Part B: graph statistics

```
.\partB_all data
```

Builds the adjacency list for every size and writes one `data/graph_N_stats.txt` per graph and
`data/partB_summary.csv` (vertices, arcs, edges, average degree, maximum degree).

### 5. Parts C and D: single queries

```
.\partC_dijkstra data/graph_10000_edges.csv --query 5 9000
.\partD_astar    data/graph_10000_edges.csv data/graph_10000_nodes.csv --query 5 9000
```

Print the cost, the complete vertex sequence, vertices explored, edges examined and execution time. Use
`--queries data/queries_10000.csv` instead of `--query S D` to run a whole query file. Output files:
`data/graph_N_dijkstra_results.csv` / `_paths.csv` and `data/graph_N_astar_results.csv` / `_paths.csv`.
Vertex ids are the 0-indexed ids of the CSV files. A pair with no connection prints "no path" (cost -1).

### 6. Part E: all sizes, averages, table, plots

```
.\partE_experiments data
python plot_results.py data/results
```

Output in `data/results/`: `partE_table.md` (the experiment table and the A*-versus-Dijkstra ratios),
`partE_summary.csv`, `partE_per_query.csv`, `partE_run_info.txt` and `plots/` (time, vertices explored, edges
examined, A*/Dijkstra ratio, per-query time spread). Option: `--repeat R` (timed runs per search, default 5).

## Preprocessing details

- DIMACS node ids are 1-indexed and are shifted to 0-indexed.
- Coordinates are integers in units of 10^-6 degrees and are divided by 10^6 to give degrees.
- Arc cleaning: self-loops and non-positive weights are dropped (none occur in this graph); parallel arcs are merged
  by keeping the minimum weight (90,850 merged). The graph is a single connected component, so no vertices are removed.
- Subgraphs are the first N vertices reached by BFS from a fixed random seed vertex (chosen from `--seed`).
  Only arcs with both endpoints inside the set are kept, and vertices are renumbered 0..N-1 in BFS order. A BFS ball
  is always connected, and the same seed vertex is used for every N, so the subgraphs are nested.
- The edge weight is the road distance from the distance graph. **Unit:** **[fill in after running: the DIMACS
  documentation gives metres; `data/heuristic.json` shows the median of w / haversine(m). A median near 1 means
  metres; a median near 10 means units of 0.1 m. State your result and use it when reporting costs.]**
- Edges are stored as directed arcs; every road appears in both directions, so *edges = arcs / 2*. Reported average
  degree is arcs / vertices; maximum degree is the largest out-degree.

## Algorithms

- **Dijkstra:** binary-heap min-priority queue (`std::priority_queue` with `std::greater`), lazy deletion, stops when
  the destination is settled. Time complexity O((V + E) log V), space O(V + E).
- **A\*:** `f(v) = g(v) + h(v)` with `h(v) = floor(scale * haversine(v, destination))`. The scale is computed by the
  program as min(w / haversine) over all arcs of the loaded graph, so `h` never overestimates (admissible) and
  satisfies `h(u) <= w(u,v) + h(v)` (consistent). The program prints the scale it uses.
- **Path reconstruction:** explicit, following the parent array from the destination back to the source.
- **Disconnected pairs:** reported as "no path"; the search ends when the queue is empty.

## Metric definitions

- **Vertices explored:** vertices settled (popped from the queue and not stale) before the destination is reached.
- **Edges examined:** outgoing edges looked at from settled vertices.
- **Execution time:** wall-clock time per query, including allocating the distance and parent arrays and rebuilding the
  path. Graph loading and the one-off heuristic setup are excluded.

## Troubleshooting

- **File not found:** check your working directory (the project root) and the file names you pass to `--gr` and `--co`.
- **C++ program cannot open CSV files:** run it from the project root and give the `data/...` paths as shown above.
- **`The term '.\partB_all' is not recognized`:** the compile step failed or was skipped; compile again and check the output.
- **`nodes file has no lat/lon columns`:** rerun `preprocess.py` with `--co` pointing at the `.co.gz` file.
- **A* explores nearly as many vertices as Dijkstra:** look at the heuristic scale printed by `partD_astar` and shown in
  `partE_table.md`. A small scale means some edge weights are much shorter than their straight-line distance, which is a
  property of the data, not a bug.
- **Editor shows errors in standard headers:** this is an IntelliSense issue. Trust the compiler output.
